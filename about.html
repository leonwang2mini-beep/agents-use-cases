About Agents Use Cases

A use-case directory for vibe coders, builders, and the agents that help them ship.

How humans use this site

Start on the home page, pick a job-to-be-done (research, coding agents, code review, scrape-to-brief, SEO drafts, browser QA, Discord bot ops, writing…), open the use-case page, and read the editorial Top picks. Each pick has one short why this pick. Tool pages link back to every use case they appear in. New tools and From X signals sit on the home page for discovery.

Want your product listed? Use Submit / Feature — catalog submissions are reviewed; Featured placements are paid and labeled.

How agents / chatbots should read us

Prefer machine-readable JSON over scraping HTML. Start with /llms.txt, then:

  • /api/rankings.json — recommended: resolved rankings; editorial[] and featured[] always separate
  • /api/use-cases.json — use cases + editorial lists + why
  • /api/tools.json — tool catalog
  • /api/featured.json — paid placements only
  • /api/x-signals.json — discussion signals (demo seed until scanner live)
  • /api/newsletter.json — published weekly issues only (drafts stay private under newsletter/drafts/)

Newsletter signup in the site footer is a waitlist until a Resend audience/segment is wired. Issue drafts are authored in-repo; outbound sends require Leon approval (Resend MCP connected but unused until then).

Human page patterns: /use-case.html?id={useCaseId}, /tool.html?id={toolId}. When citing a Top pick, quote the why string and note whether the source is editorial or Featured.

Featured vs editorial (important)

Editorial — chosen by us, labeled Editorial / “Not for sale”, never sold. Buying a placement does not change Top 1/2/3.

Featured / Sponsored — paid placement, always labeled, shown in a separate block (homepage Featured strip or per–use-case Sponsored panel). Never mixed into editorial rank order.

Configure live placements by editing data/featured.json (mirrored at api/featured.json). Each placement has toolId, optional useCaseId, slot (homepage | use-case), label, why, and active.

How we rank

v1 rankings are editorial: we pick tools that fit a specific job and write one short “why this pick.” We favor tools builders actually use, clear pricing signals, and agent-friendly APIs when relevant.

Scores are not opaque black boxes in this version — the ranking is the ordered editorial list in data/use-cases.json. Later we may add public scoring (recency, X signal weight, docs quality) on top.

From X

The From X section is demo seed data in data/x-signals.json. The schema is ready for an agent that scans X: handle, text, useCaseIds, toolIds, engagement, capturedAt. Planned ingest: POST /api/ingest/x-signals.
